# 주차별 과제 루브릭 (10점)

과제 노트북의 각 문제는 아래 네 기준으로 나누어 채점합니다. 문제 배점(2점 또는 3점)에 비율을 곱해 계산합니다.

| 기준 | 비율 | 우수 (100%) | 보통 (50%) | 미흡 (0%) |
|---|---:|---|---|---|
| **기능** | 50% | 자동 확인 모두 통과, 채점자가 다른 입력으로 실행해도 맞음 | 일부 통과, 또는 특정 입력에서만 맞음 | 실행 오류, 미작성, **하드코딩** |
| **검증** | 20% | 정상·경계·오류 사례를 직접 추가로 확인한 흔적 | 제공된 자동 확인만 실행 | 실행하지 않음 |
| **이해** | 15% | 버그 보고서·주석·기록에서 원인과 수정 이유를 자신의 말로 설명 | 무엇을 했는지만 나열 | 설명 없음, 또는 코드와 불일치 |
| **AI 기록·성찰** | 15% | 프롬프트, 채택·수정 내용, 검증 방법이 구체적이고 코드와 일치 | 도구 이름과 용도만 | 기록 없음 |

## 공통 감점

| 상황 | 처리 |
|---|---|
| 결과값을 직접 써 넣어 자동 확인만 통과 | 해당 문제 기능 점수 0 |
| *다시 시작 및 모두 실행*에서 오류 | 오류가 난 문제 이후 기능 점수 50% |
| 입력 데이터를 바꾸면 안 되는 문제에서 원본 변경 | 해당 문제 기능 점수 50% |
| `except:` / `except Exception: pass`로 오류를 숨김 (6주차 이후) | 해당 문제 이해 점수 0 |
| 지각 제출 | 하루 10% 감점, 3일 이후 미제출 처리 (학기 공지 우선) |

## AI 활용과 관련된 원칙

- AI 사용 **자체는 감점 대상이 아닙니다.** 사용을 숨기거나, 설명할 수 없는 코드를 제출하는 것이 문제입니다.
- AI가 만든 코드를 그대로 제출했더라도, 검증과 기록이 충실하면 검증·AI 기록 점수를 받을 수 있습니다.
- 기록과 코드가 일치하지 않거나, 다른 학생과 같은 오류·같은 표현이 반복되면 구술 확인을 할 수 있습니다.

## 채점 예시 (3점 문제)

| 기준 | 상황 | 점수 |
|---|---|---:|
| 기능 (1.5) | 자동 확인 통과, 다른 입력에서도 맞음 | 1.5 |
| 검증 (0.6) | 경계값 테스트 2개 직접 추가 | 0.6 |
| 이해 (0.45) | 원인을 "range 끝이 미만이라서"처럼 설명 | 0.45 |
| AI 기록 (0.45) | 도구 이름만 있고 수정 내용 없음 | 0.2 |
| | **합계** | **2.75** |
